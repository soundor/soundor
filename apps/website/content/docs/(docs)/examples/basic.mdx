**Edit code** opens its UI files under the plugin: change them and the plugin
runs your version.

One Soundor plugin, a gain, built for two runtimes from one config and one UI.

```text
soundor.config.ts   identity, a resizable editor, the `gain` parameter,
                    both runtimes
src/main.tsx        mounts src/App.tsx, and its resize grip
src/App.tsx         the plugin UI (@soundor/react): a fader, the host's
                    transport, a preset name kept in soundor:storage,
                    stacked when the editor is narrow
src/ResizeGrip.tsx  a resize grip of its own, in the view's corner

native/             the audio processing, in Rust: applies `gain`
                    (src/lib.rs), with its tests (tests/)
runtimes/juce/      JUCE: the plugin, which runs native/
runtimes/web/       Web: the browser host, which runs native/ compiled to
                    WebAssembly
```

The UI is the same in both, and so is the audio: both runtimes run the Rust
processing in `native/src/lib.rs`, a gain ramped from block to block:

```rust
fn process(&mut self, ctx: &mut ProcessContext) {
    let target = ctx.params.gain;
    let frames = ctx.audio.frames();
    let step = if frames == 0 { 0.0 } else { (target - self.gain) / frames as f32 };
    for channel in ctx.audio.channels() {
        let mut gain = self.gain;
        for sample in channel {
            *sample *= gain;
            gain += step;
        }
    }
    self.gain = target;
}
```

`cargo test --manifest-path native/Cargo.toml` (or `pnpm test:rust`) tests it
in plain Rust. The Web host compiles the same crate to WebAssembly and runs it
in an AudioWorklet.

## In the browser

```sh
pnpm dev:web     # soundor dev web: the host, with an inspector
pnpm build:web   # soundor build web: a static site in .soundor/dist/web
```

Press ▶ to play the host's input (an oscillator, or an audio file of yours)
and move the fader: the plugin UI sets `gain`, and the processor follows it.
Its editor is resizable (`editor: { resizable: true }`): drag the handle at
the view's corner and the UI is laid out again at the new size, as in the
JUCE editor. `App.tsx` reads the size with
[`useViewSize()`](/docs/hooks/use-view-size): it shows it, and narrower than
640 logical pixels it stacks the fader and the panel instead of setting them
side by side, the same in both runtimes.

The grip in the view's own corner (`src/ResizeGrip.tsx`) resizes it too:
dragged, or focused (Tab) with the arrow keys, it asks for a size with
[`requestEditorSize()`](/docs/api/ui#asking-for-a-size), and hides where the
editor's size cannot be asked for (`?embed`). The editor centres its layout
in a window larger than its 1600×1200 maximum (`fit: 'contain'`), so a host
making it larger still leaves the grip in the middle of the window; Orbit
covers the window instead.

The build works from any path and inside an iframe, so a docs page can show
the code above next to the running plugin:

```html
<iframe src="examples/basic/" width="840" height="720"></iframe>
```

## As a JUCE plugin

```sh
pnpm dev          # soundor dev juce: a debug build, the VST3 opened in the host
pnpm build:juce   # soundor build juce: VST3 and Standalone in .soundor/dist/juce
```

JUCE must be installed (see `soundor doctor`).

## Tests

```sh
pnpm test
pnpm typecheck
pnpm build:web
```

Behavioral tests render the real `App` with `@soundor/testing-library/react`,
semantic queries, and `userEvent.setup()`. The four testing dependencies are
explicitly declared. These run against the simulated runtime, with no browser or
native engine. See the [Testing guide](/docs/testing). Root repository
checks exclude examples; run these commands explicitly.
