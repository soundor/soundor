Parameters are the values the plugin exposes to its host: a gain, a bypass
switch, a mode selector. Declare them in `soundor.config.ts`, use the generated
`soundor:parameters` module from the UI, and connect them to audio processing in
each runtime.

## Declare parameters

The config accepts four parameter types:

```ts
parameters: [
  { type: 'float', id: 'gain', label: 'Gain', min: 0, max: 1, default: 0.5 },
  { type: 'int', id: 'voices', label: 'Voices', min: 1, max: 16, default: 4 },
  { type: 'bool', id: 'bypass', label: 'Bypass', default: false },
  {
    type: 'enum',
    id: 'mode',
    label: 'Mode',
    values: ['clean', 'warm'],
    default: 'clean',
  },
],
```

Float and integer parameters may also have a display `unit`. IDs are unique
within the plugin. Generated declarations expose the corresponding value types:
numbers, booleans, and enum string unions.

## Read, write, and subscribe

```ts
import { parameters } from 'soundor:parameters';

const gain = parameters.gain.get();
parameters.gain.set(0.75);
const unsubscribe = parameters.gain.subscribe((value) => {
  console.log('Gain changed:', value);
});

// Call when this subscription is no longer needed.
unsubscribe();
```

`info` exposes the declaration, including the label, range where applicable,
and default. Numeric writes are clamped to their range; integer values are
rounded. Wrong value types fail, and enum writes must be declared choices.
Subscribers hear changes rather than repeated writes of the same value.

In React, use `useParameter(parameters.gain)` to read and subscribe with the
component's lifecycle. Keep the parameter as the value source so host automation,
preset restoration, and other views can update the displayed value.

## Group a user edit into a gesture

A gesture tells the host when a user starts and finishes changing a parameter.
For a discrete action, bracket the write:

```ts
const gain = parameters.gain;
gain.beginGesture();
try {
  gain.set(gain.info.default);
} finally {
  gain.endGesture();
}
```

For a drag, begin on pointer down, set values as the pointer moves, and end
when the interaction finishes or is cancelled. Balance gestures across every
exit path. Gestures can nest; only the outermost boundaries reach the host.
In the JUCE runtime these map to JUCE's parameter change gestures, allowing a
DAW to record the interaction as automation.

## Connect parameters to audio

In a JUCE plugin the parameter API is backed by the processor's
`AudioProcessorValueTreeState`. Host automation, preset restoration, and UI
changes use that same state. Parameter listeners only set lock-free flags;
JavaScript subscribers run later on the message thread.

Your processor reads the parameter state and applies it to audio buffers.
JavaScript does not process the audio or run on the audio thread. The
[basic example](/docs/examples/basic) shows the C++ gain implementation alongside
its browser implementation.

In the browser the UI, audio setup, and host controls share one parameter
store. Subscribe from `runtimes/web/src/audio.ts` to update a Web Audio node,
and return a cleanup function that unsubscribes and disconnects the graph.
See [Web Audio setup](/docs/web-runtime#audio-raw-web-audio).

## Test parameter behavior

The test runtime implements parameter validation, changes, and nested gestures.
Use the [testing helpers](/docs/testing#parameters-host-and-native-services) to
simulate host-side values and inspect UI behavior. A component test can verify
that a fader displays an automated change or that Reset restores the declared
default. Audio processing and real DAW automation require their own integration
checks.
