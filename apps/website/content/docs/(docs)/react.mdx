## No DOM

In a native plugin the UI runs inside Soundor's embedded JavaScript runtime,
without a browser: there is no DOM, no `window`, no CSS. The web runtime
draws the same Soundor nodes with DOM elements. Either way the UI sees the
same components, the same layout and the same events, so it is written once:

- **Components** are React Native's: [`View`](/docs/components/view),
  [`Text`](/docs/components/text), [`Pressable`](/docs/components/pressable),
  [`TextInput`](/docs/components/text-input),
  [`ScrollView`](/docs/components/scroll-view),
  [`Image`](/docs/components/image), plus [`Canvas`](/docs/components/canvas)
  for code that draws, and overlays: [`Portal`](/docs/components/portal),
  [`Modal`](/docs/components/modal), [`FocusScope`](/docs/components/focus-scope).
  Strings go in a `Text`.
- **Styles** are objects, not CSS: flexbox, a column by default
  ([Style](/docs/components/style)).
- **Events** are Web-style pointer, wheel, key and focus events that capture
  and bubble ([Events](/docs/components/events)), in the view's logical
  pixels ([coordinates](/docs/components/events#coordinates)).
- **Accessibility** is React Native's props, which every runtime presents to
  its platform's screen readers ([Accessibility](/docs/components/accessibility)).
- **Animation** runs in the runtime, not in React:
  [`Animated.View`](/docs/components/animated-view) animates style changes,
  and `useAnimationFrame` draws a canvas every frame.

## State and parameters

What the host automates and saves is a parameter, not React state: read one
with `useParameter`, and change it with `set()`, so the host, its automation
and presets, and every view show the same value.

```tsx
const gain = useParameter(parameters.gain);
// …
parameters.gain.beginGesture();
parameters.gain.set(next); // while dragging
parameters.gain.endGesture();
```

Keep React state for what only the UI knows: a tab, a menu that is open.
Persistent preferences go in [`soundor:storage`](/docs/api/storage), files
in [`soundor:fs`](/docs/api/fs). See [Parameters](/docs/parameters) and
[`@soundor/react`](/docs/api/react) for rendering and the hooks.

## Testing

Install `vitest`, `@soundor/vitest`, `vitest-environment-soundor`, and
`@soundor/testing-library` as direct development dependencies. Configure
`plugins: [soundor()]` from `@soundor/vitest` and `test.environment: 'soundor'`.
Tests run against a simulated Soundor runtime, using the real React reconciler.

```tsx
import { Pressable, Text } from '@soundor/react';
import { render, screen, userEvent } from '@soundor/testing-library/react';
import { expect, test, vi } from 'vitest';

test('activates a control', async () => {
  const onPress = vi.fn();
  const user = userEvent.setup();
  await render(
    <Pressable onPress={onPress}>
      <Text>Save</Text>
    </Pressable>,
  );
  await user.click(screen.getByRole('button', { name: 'Save' }));
  expect(onPress).toHaveBeenCalledOnce();
});
```

See the [Testing guide](/docs/testing) for installation, configuration,
queries, mocks, async updates, animation time, and limits. In this repository,
`pnpm --filter @soundor/react test` runs the private `testing` workspace, which
owns its direct testing dependencies and keeps the renderer's build independent
of its test tools.
