title: Canvas
description: Pixels code draws, with a 2D or a WebGL 2 context.
---

A `Canvas` is pixels your code draws, like an HTML `<canvas>`: get its
context from its node, in an effect or on every frame.

<Snippet name="canvas" height={200} />

- **Contexts:** `ref.current.getContext('2d')` gives a
  `CanvasRenderingContext2D` (drawn with Skia natively), the same object every
  time. `getContext('webgl2')` gives a `WebGL2RenderingContext` on the GPU, or
  null where there is no acceptable GPU; Three.js runs on it unmodified.
- **Size:** `width` and `height` are the drawing buffer's, 300 by 150 by
  default, and the buffer is stretched over the box. Setting either clears the
  canvas, so draw again after. For crisp lines, use
  [`useCanvasSize`](/docs/hooks/use-canvas-size): give the canvas a size by its
  style or by flexbox, and it keeps the buffer exactly the device pixels the box
  covers. That holds at any display scale, through the host's scaling and an
  editor's zoom, and whatever resizes the box, and it re-renders when the size
  changes. Without a style, the box is the buffer's size in logical pixels.
- **Every frame:** `useAnimationFrame` calls your drawing code before each
  frame, while the component is mounted ([hooks](/docs/hooks)).
- **What 2D draws:** paths, rectangles, text, gradients, patterns, images,
  `ImageData`, transforms and compositing. Shadows, `filter`, `Path2D` and
  `DOMMatrix` throw rather than draw something else: see the
  [canvas reference](/docs/contribute/engine-reference#soundorui).
- **To assistive technology** a canvas is decorative unless it is given a
  label, a role or `accessible`, like an image.
