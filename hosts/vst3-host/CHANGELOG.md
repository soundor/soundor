## 0.1.0

### Minor Changes

- [#214](https://github.com/soundor/soundor/pull/214) [`cdbebe4`](https://github.com/soundor/soundor/commit/cdbebe4624eeb57c7d7be6840d10e2a0e92b2cf7) Thanks [@dm-balakin](https://github.com/dm-balakin)! - Add `@soundor/vitest-e2e`: Vitest tests of a built VST3 plugin in the real host, with `launchPlugin()`, `launchHost()`, the `soundor({ vst3 })` plugin and the `toBeVisible`, `toBeHidden` and `toHaveText` matchers. `Vst3Plugin` from `@soundor/driver/vst3` gains locators that survive a reopened editor, `pointer`, `keyboard`, `screenshot()` and `parameter()`. `Vst3Host` gains `parameter(title)`.

- [#211](https://github.com/soundor/soundor/pull/211) [`d25004f`](https://github.com/soundor/soundor/commit/d25004f4fc7eb2926719f640861e75525f25116a) Thanks [@dm-balakin](https://github.com/dm-balakin)! - New package: a standalone VST3 host for tests and development. `launchHost()` starts a native host process that loads a `.vst3` bundle by path, headless or with the plugin's editor in a native window, and processes audio offline: buses and channel layouts, sample-accurate parameter changes, MIDI in and out, transport, latency and tail, state, reset and recreate. Its executables ship as platform packages for Linux x64, macOS (universal) and Windows x64, installed as exact-version optional dependencies.

### Patch Changes

- [#213](https://github.com/soundor/soundor/pull/213) [`c6a011f`](https://github.com/soundor/soundor/commit/c6a011f5fcbe805ff4c9def2b1d3ddc50dadf89b) Thanks [@dm-balakin](https://github.com/dm-balakin)! - Add `@soundor/driver/vst3`: `launch()` runs a Debug build of a Soundor plugin in the VST3 host, in a private DevTools session, and gives a Driver for its UI beside the host for its audio. `@soundor/vst3-host` is an optional peer, and `@soundor/devtools-server` is now a dependency of the Driver. In the host, a handler that a plugin unregisters from Linux's run loop is released at once rather than on a later turn, which crashed `recreate()` on JUCE plugins, whose handlers can be gone by then.

- [#221](https://github.com/soundor/soundor/pull/221) [`658a9c0`](https://github.com/soundor/soundor/commit/658a9c09dc9516a4084350ee655d431d7aa10929) Thanks [@dm-balakin](https://github.com/dm-balakin)! - A grip drag ends where the pointer does, even when the mouse button is released in the same frame as its last move.

- [#219](https://github.com/soundor/soundor/pull/219) [`f485471`](https://github.com/soundor/soundor/commit/f48547140e2547b3358fd22060b79fd345ca0168) Thanks [@dm-balakin](https://github.com/dm-balakin)! - Add `prepareHost({ mode: 'published' })`, which uses the published executable or fails rather than building, and `selectHost()`, which reports whether a published executable matches this checkout. A CI artifact keeps working after an upload loses its file modes.

- [#222](https://github.com/soundor/soundor/pull/222) [`7fb3f13`](https://github.com/soundor/soundor/commit/7fb3f13f2e3435764e0c5c84ba0b2c44ef805430) Thanks [@dm-balakin](https://github.com/dm-balakin)! - `soundor dev juce` opens the VST3 in `@soundor/vst3-host`, now an optional peer, when the project installs it and `formats` has `vst3`; otherwise the Standalone, as before. `juceRuntime({ dev: { launch } })` chooses (`'vst3'`, `'standalone'` or `false`), and the `v` and `s` keys open either at any time. The plugin's state is kept in `.soundor/state/juce/vst3.json` between launches of the host. New projects with the JUCE runtime get the host as a devDependency. In the host, `launchHost({ detached: true })` runs it in a process group of its own, so that a terminal's Ctrl+C reaches only Node. Runtimes get `ctx.paths.state`, `.soundor/state/<id>`, for what they keep between sessions and cannot make again. A local build of the host no longer needs a static libstdc++ (Fedora's `libstdc++-static`); only the published executables link it.

- [#224](https://github.com/soundor/soundor/pull/224) [`e30a086`](https://github.com/soundor/soundor/commit/e30a08690b7d67da02fe73296cfb55e22fafa6a3) Thanks [@dm-balakin](https://github.com/dm-balakin)! - On Linux, every plugin build and every build of the VST3 host links the C++ runtime statically, and a plugin's is hidden from other plugins, so a plugin no longer needs a `libstdc++` as new as its build machine's, and needs neither `libatomic` nor, as a VST3, `libasound`. A build machine now needs the compiler's static C++ library (Fedora, RHEL: `libstdc++-static`): without it, a build stops first and says what to install, and `soundor doctor` reports it. `soundor build` prints the glibc a release needs, and `soundor doctor` warns when the machine's is newer than the 2.39 of Ubuntu 24.04, as a release built there may not load on older systems.

- [#223](https://github.com/soundor/soundor/pull/223) [`5f9a5a3`](https://github.com/soundor/soundor/commit/5f9a5a33ef84f916d4b295a91b6ca0bc1343f50e) Thanks [@dm-balakin](https://github.com/dm-balakin)! - A JUCE plugin now runs on macOS 12 or later by default, whatever macOS it is built on, where it used to require the macOS of the machine that built it. `juceRuntime({ macos: { deploymentTarget } })` asks for a newer minimum, and anything below the engine's 12.0 is refused. `soundor doctor` checks for the Metal tools a source build of the engine needs. A prebuilt macOS engine no longer lists a framework by its path inside the Xcode that built it. Source builds of the VST3 host target macOS 12 too, as its published executables do.

- [#227](https://github.com/soundor/soundor/pull/227) [`b836a81`](https://github.com/soundor/soundor/commit/b836a8181614f844c77eae91ea9d548412ab3b15) Thanks [@dm-balakin](https://github.com/dm-balakin)! - Avoid CMake CMP0169 deprecation warnings when fetching the host's dependencies, while preserving the existing minimum CMake version.

- [#212](https://github.com/soundor/soundor/pull/212) [`7535f74`](https://github.com/soundor/soundor/commit/7535f741e47169c460a631e95b8c2d122a178ca3) Thanks [@dm-balakin](https://github.com/dm-balakin)! - In the host presentation, resizing or maximizing the window now changes only the stage around the editor, as in the web host, whether or not the plugin can be resized, and the window's minimum keeps room for it. Parameter checkboxes match the web panel's. Open the editor at the display's scale on Linux in the host presentation, as the interface around it already was. Deliver events waiting in the queue of a plugin's X connection, which a round trip of its own could leave unnoticed until the next event, such as a click that seemed to do nothing. Add a plugin resize grip to the host interface, present each change of the editor's geometry as one frame on Linux (the host draws the editor's last complete image, through XComposite, and answers the window manager's sync requests), keep the editor centred with its corner under the pointer and within the stage's room as in the web host, for the grip and for the plugin's own requests, and preserve extra stage space when the plugin constrains a window resize. Handle native window-manager changes asynchronously, keep maximized windows fixed, and target the current monitor's refresh rate. Retain accelerated host drawing with a software fallback, and make audio startup explicit so Start/Stop responds consistently on the first click. The editor presentation's window can no longer be maximized or minimized, and on Linux it now opens at the display's scale. Its border asks the plugin for each size through VST3 alone, presents the editor's last complete image until the editor has painted, and the window takes the editor's size once the drag stops.
